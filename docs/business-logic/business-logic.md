# Бізнес-логіка — AutoDealerCRM

**Версія:** 1.0  
**Дата:** 2026-11-02  
**Статус:** Актуальна

---

## 1. Предметна область

Система обслуговує бізнес-процеси дилера, що закуповує вживані автомобілі на американських аукціонах Copart та IAAI та перепродає їх в Україні. Ключовою цінністю є прозорість стану доставки для покупця та захист комерційної інформації (собівартість, повний VIN) від несанкціонованого доступу.

---

## 2. Основні сутності

### 2.1. Лот автомобіля (CarLot)

Лот є центральною сутністю системи. Він описує конкретний автомобіль, куплений або запланований до купівлі на аукціоні.

**Поля лоту:**

| Поле | Тип | Видимість | Опис |
|------|-----|-----------|------|
| Id | int | Внутрішнє | Первинний ключ |
| Make | string | Публічна | Марка автомобіля (Toyota, Honda...) |
| Model | string | Публічна | Модель (Camry, Civic...) |
| Year | int | Публічна | Рік випуску |
| Mileage | int | Публічна | Пробіг у милях (відображається в км після конвертації) |
| PublicPrice | decimal | Публічна | Ціна продажу для покупця (USD) |
| Status | enum | Публічна | Статус доставки |
| VinCode | string | **Конфіденційна** | Зашифрований VIN-код (17 символів), видно менеджеру |
| AuctionCost | decimal | **Конфіденційна** | Зашифрована собівартість закупівлі (USD), видно менеджеру |
| AuctionName | string | Внутрішнє | Назва аукціону (Copart / IAAI) |
| AddedAt | DateTime | Внутрішнє | Дата додавання лоту |

**Правила:**
- VIN-код складається рівно з 17 символів. Введення VIN іншої довжини заборонено.
- Публічна ціна повинна бути більшою за 0.
- Собівартість не може перевищувати публічну ціну більш ніж у 10 разів (перевірка на рівні сервісу для виявлення помилок введення).
- Лот не може бути видалений, якщо він пов'язаний з активною заявкою покупця.

### 2.2. Статус доставки (DeliveryStatus)

Статус описує поточний етап переміщення автомобіля від аукціону до покупця.

```
[На аукціоні] → [В дорозі] → [На митниці] → [В наявності]
```

**Правила переходів:**
- Прямий перехід між статусами можливий лише у зазначеному порядку.
- Перехід до попереднього статусу заборонений (автомобіль не може «повернутися з дороги на аукціон»).
- Виняток: адміністратор може встановити довільний статус для виправлення помилки.

### 2.3. Заявка покупця (BuyerRequest)

Заявка фіксує намір покупця отримати консультацію або підібрати автомобіль.

**Поля заявки:**

| Поле | Тип | Видимість | Опис |
|------|-----|-----------|------|
| Id | int | Внутрішнє | Первинний ключ |
| FullName | string | Менеджер | ПІБ покупця |
| Phone | string | **Конфіденційна** | Зашифрований номер телефону |
| DesiredModel | string | Менеджер | Побажання щодо моделі авто |
| CreatedAt | DateTime | Менеджер | Дата та час подання заявки |
| IsProcessed | bool | Менеджер | Ознака обробки заявки |

**Правила:**
- Номер телефону зберігається у зашифрованому вигляді (AES-256). Розшифрування лише на рівні сервісу.
- Заявка не прив'язана до конкретного лоту — покупець описує бажане авто текстом.
- Одна заявка — один контакт. Система не перевіряє дублікати телефонів (навчальний проєкт).

### 2.4. Обліковий запис користувача (AppUser)

| Поле | Опис |
|------|------|
| Id | Унікальний ідентифікатор |
| UserName | Логін (email або довільний рядок) |
| PasswordHash | Хеш пароля (PBKDF2 через ASP.NET Core Identity) |
| Role | Роль: Manager або Admin |
| IsBlocked | Ознака блокування |
| CreatedAt | Дата створення |

**Правила:**
- Адміністратор може бути лише один (seed-акаунт при першому запуску).
- Менеджерів може бути необмежена кількість.
- Заблокований менеджер не може увійти, навіть якщо введе вірний пароль.
- Адміністратор не може заблокувати сам себе.

### 2.5. Запис журналу безпеки (AuditLogEntry)

| Поле | Опис |
|------|------|
| Id | Первинний ключ |
| Timestamp | Дата та час події (UTC) |
| EventType | Тип події (LoginSuccess, LoginFailed, Logout, UserBlocked, LicenseUploaded...) |
| ActorName | Логін користувача, що виконав дію (або «Anonymous») |
| TargetName | Об'єкт дії (наприклад, логін менеджера, що заблокований) |
| IpAddress | IP-адреса джерела запиту |
| Details | Додаткова інформація (опціонально) |

**Правила:**
- Записи журналу не можуть бути видалені або відредаговані через інтерфейс.
- Журнал зростає монотонно (append-only на рівні бізнес-логіки).

### 2.6. Ліцензія (LicenseStatus)

Система підтримує два режими роботи:

| Режим | Опис |
|-------|------|
| Demo | Ліцензійний файл відсутній або недійсний. Відображається «Demo» у заголовку. |
| Licensed | Ліцензійний файл пройшов криптографічну перевірку. Відображається ім'я власника та термін дії. |

**Правила:**
- Ліцензійний файл `dealer.lic` перевіряється при кожному завантаженні адміністратором.
- Перевірка включає: формат файлу, відповідність підпису, термін дії.
- Прострочена ліцензія переводить систему в режим «Demo».

## 3. Ключові бізнес-процеси

### 3.1. Додавання нового лоту менеджером

1. Менеджер вводить усі поля лоту у форму.
2. Сервіс перевіряє формат VIN (17 символів, латиниця/цифри).
3. Сервіс шифрує VIN та собівартість перед збереженням у БД.
4. Лот зберігається зі статусом «На аукціоні» за замовчуванням.
5. Лот стає видимим у публічному каталозі з маскованим VIN.

### 3.2. Надсилання заявки покупцем

1. Гість заповнює форму (ПІБ, телефон, побажання).
2. Сервіс шифрує номер телефону перед збереженням.
3. Заявка зберігається в БД з `IsProcessed = false`.
4. Менеджер бачить заявку у своєму списку та може позначити її як оброблену.

### 3.3. Перевірка ліцензії

1. Адміністратор завантажує файл `dealer.lic` через форму.
2. Система зчитує вміст файлу та перевіряє HMAC-SHA256 підпис за допомогою секретного ключа.
3. Якщо підпис вірний і термін дії не минув — статус змінюється на «Licensed».
4. Подія записується до журналу безпеки незалежно від результату перевірки.

### 3.4. Вхід у систему

1. Користувач вводить логін і пароль.
2. Система порівнює хеш введеного пароля з хешем у БД.
3. Якщо акаунт заблокований — вхід відхиляється навіть при вірному паролі.
4. Результат (успішний / невдалий) записується до журналу безпеки з фіксацією IP-адреси.
5. При успішному вході видається захищена cookie-сесія.
