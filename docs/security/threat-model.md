# Модель загроз — AutoDealerCRM

**Версія:** 1.0  
**Дата:** 2026-11-02  
**Методологія:** STRIDE (Microsoft Threat Modeling)  
**Скоуп:** Весь застосунок AutoDealerCRM (єдина модель для навчального проєкту)

---

## 1. Межі аналізованої системи

Аналізується веб-застосунок AutoDealerCRM, що виконується на локальному сервері під .NET 8, взаємодіє з базою даних MS SQL Server і обслуговує трьох типів акторів: Гість, Менеджер, Адміністратор.

**Межа довіри №1:** між браузером (зовнішній суб'єкт) і ASP.NET Core застосунком.  
**Межа довіри №2:** між ASP.NET Core застосунком і базою даних SQL Server.

## 3. Модель порушника

| Тип порушника | Рівень доступу | Технічні можливості | Доступні інтерфейси |
|---------------|----------------|---------------------|---------------------|
| **П1 — Зовнішній зловмисник** | Неавтентифікований | Середні (знання веб-атак: SQLi, XSS, CSRF, brute-force) | HTTP-інтерфейс (публічні сторінки) |
| **П2 — Недобросовісний покупець** | Неавтентифікований | Низькі (маніпуляція формою, URL-перебір) | HTTP-інтерфейс (публічні сторінки) |
| **П3 — Скомпрометований менеджер** | Автентифікований, роль Manager | Середні (доступ до закритих сторінок менеджера) | HTTP-інтерфейс (менеджерська частина), БД через застосунок |
| **П4 — Зловмисний адміністратор** | Автентифікований, роль Admin | Розширені (доступ до всіх функцій системи) | Весь інтерфейс, SSMS (якщо є фізичний доступ) |
| **П5 — Зловмисник з фізичним доступом до сервера** | Немає акаунту в системі | Розширені (доступ до файлів, SSMS, змінних середовища) | ОС сервера, SSMS |

## 4. STRIDE-аналіз загроз

### 4.1. Зовнішні суб'єкти (Гість, Менеджер, Адміністратор)

#### S — Spoofing (Підміна суб'єкта)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-S-01 | Підбір пароля (brute-force) до акаунту менеджера або адміністратора | Форма входу | П1, П2 | Хешування паролів PBKDF2 (ускладнює перебір); блокування акаунту після N невдалих спроб (реалізується за потреби) |
| T-S-02 | Викрадення cookie-сесії та використання під чужим іменем | Cookie автентифікації | П1, П3 | `HttpOnly=true` (неможливо прочитати через JS); `SameSite=Strict` (захист від CSRF-крадіжки) |
| T-S-03 | Спроба доступу до захищених маршрутів без авторизації (перебір URL) | Маршрути /Manager/*, /Admin/* | П1, П2 | `[Authorize(Roles=...)]` на всіх захищених контролерах; перенаправлення на /Account/Login |

#### T — Tampering (Несанкціонована зміна)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-T-01 | Підробка POST-запиту від імені менеджера для зміни даних лоту | HTTP-запит до ManagerController | П1 | `[ValidateAntiForgeryToken]` на всіх POST-методах |
| T-T-02 | Підробка ліцензійного файлу `dealer.lic` | Файл dealer.lic | П4, П5 | Криптографічна перевірка HMAC-SHA256 підпису при кожному завантаженні |
| T-T-03 | Пряме редагування зашифрованих полів у БД через SSMS | Таблиці CarLots, BuyerRequests | П5 | AES-шифрування унеможливлює читання або осмислену зміну значень без ключа; порушення цілісності виявляється при розшифруванні |
| T-T-04 | Модифікація записів журналу безпеки для приховання дій | Таблиця AuditLogs | П4, П5 | Відсутність методів Update/Delete у AuditLogService; на рівні БД — відсутність UPDATE-прав для акаунту застосунку (рекомендація) |

#### R — Repudiation (Можливість заперечення)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-R-01 | Менеджер заперечує факт зміни або видалення лоту | Дії у ManagerController | П3 | Журнал безпеки фіксує значущі дії з логіном і часом (частково; повний аудит дій менеджера — можливе розширення) |
| T-R-02 | Користувач заперечує факт входу або виходу | Автентифікація | П3, П4 | AuditLog фіксує події LoginSuccess, Logout з IP-адресою та часом (UTC) |

#### I — Information Disclosure (Несанкціоноване розкриття інформації)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-I-01 | Отримання повного VIN-коду з публічного каталогу | Публічна View каталогу | П1, П2 | Маскування VIN у ViewModel гостя (перші 11 + ******); повний VIN доступний лише ролі Manager/Admin |
| T-I-02 | Читання зашифрованих полів БД (VIN, телефон, собівартість) через SSMS | Таблиці CarLots, BuyerRequests | П5 | AES-256 шифрування; без ключа дані нечитабельні |
| T-I-03 | Розкриття внутрішньої конфігурації (рядок БД, ключ шифрування) через сторінку помилки | HTTP-відповідь 500 | П1 | Відключення `developerExceptionPage` у production; нейтральна сторінка помилки |
| T-I-04 | Читання ключа шифрування з `appsettings.Development.json` у репозиторії | Репозиторій GitHub | П1 | Файл виключений з git через `.gitignore`; у репозиторії лише `appsettings.Example.json` |
| T-I-05 | Витік телефону покупця з журналу безпеки | Таблиця AuditLogs | П3, П4 | Заборона запису розшифрованих чутливих полів у журнал (вимога security policy) |
| T-I-06 | XSS-атака через поле форми заявки | Форма BuyerRequest | П1, П2 | Razor автоматично HTML-кодує виведені змінні `@Model.Field`; `X-XSS-Protection` заголовок |

#### D — Denial of Service (Порушення доступності)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-D-01 | Флуд форми заявок (спам-заявки) | POST /Home/SubmitRequest | П1 | Навчальний проєкт: відсутність rate limiting (позначено як SECURITY-TODO); рекомендовано CAPTCHA або rate limiting у production |
| T-D-02 | Виснаження пулу з'єднань до БД масовою кількістю запитів | AppDbContext | П1 | Засоби EF Core connection pooling; у навчальному контексті загроза прийнятна |

#### E — Elevation of Privilege (Підвищення привілеїв)

| ID | Загроза | Елемент | Порушник | Захід |
|----|---------|---------|----------|-------|
| T-E-01 | Менеджер намагається отримати доступ до сторінок адміністратора | Маршрути /Admin/* | П3 | `[Authorize(Roles = "Admin")]` — менеджер отримає HTTP 403 |
| T-E-02 | SQL-ін'єкція для отримання даних з таблиці AppUsers | EF Core запити | П1, П3 | Всі запити через EF Core LINQ із параметризованими запитами; raw SQL із конкатенацією заборонено |
| T-E-03 | Підміна параметра ролі у HTTP-запиті при реєстрації | Форма реєстрації | П1 | Роль встановлюється виключно сервером (хардкод при створенні менеджера адміном), не приймається з форми |

## 6. Висновки

Основні ризики для системи AutoDealerCRM сконцентровані в категоріях **Spoofing**, **Information Disclosure** та **Elevation of Privilege**. Усі критичні загрози мають конкретні контрзаходи, реалізовані засобами .NET 8 та ASP.NET Core.

Найбільш чутливим місцем системи є зберігання ключа шифрування — його компрометація (загроза T-I-04) дає зловмиснику доступ до всіх зашифрованих даних. Тому суворе дотримання правила «ключ не в репозиторії» є пріоритетом №1 безпекової реалізації.
