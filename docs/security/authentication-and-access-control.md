## 1. Логіка ідентифікації та автентифікації (ЛР №4)

### 1.1. Ідентифікація користувача
- **Ідентифікатор:** Унікальна адреса електронної пошти (`Email` / `UserName`).
- **Сценарій:** Введення логіна на сторінці `/Account/Login`. У разі відсутності користувача повертається загальне повідомлення про помилку («Невірний email або пароль») для запобігання перебору наявних акаунтів (User Enumeration).

### 1.2. Метод автентифікації
- **Фактор знання:** Пароль користувача.
- **Зберігання паролів:** Паролі ніколи не зберігаються у відкритому вигляді. Використовується алгоритм адаптивного повільного хешування **PBKDF2** (Password-Based Key Derivation Function 2) із випадковою сіллю (Salt) для кожного запису та HMAC-SHA256 (стандартна реалізація `PasswordHasher<AppUser>` в ASP.NET Core Identity).
- **Стійкість до перебору:** На відміну від швидких функцій (SHA-256), де перебір 20 паролів триває менше 0.23 мс, алгоритми класу PBKDF2/BCrypt потребують сотень мілісекунд на одну перевірку, що робить словникові атаки та brute-force неефективними.

### 1.3. Керування станом автентифікованого сеансу
- **Механізм:** Захищені сесійні Cookies (`CookieAuthentication`).
- **Параметри Cookie:**
  - `HttpOnly = true` — захист від викрадення токена сесії через XSS.
  - `SameSite = Strict` — захист від підробки міжсайтових запитів (CSRF).
  - `ExpireTimeSpan = 8 годин` з підтримкою `SlidingExpiration`.
- **Завершення сеансу:** При виклику `POST /Account/Logout` стан автентифікації скидається (`SignOutAsync()`), а сесійні куки інвалідуються.

### 1.4. Стан облікового запису та блокування
- Кожен акаунт має атрибут `IsBlocked (bool)`.
- Якщо користувача заблоковано адміністратором, перевірка блокування відбувається **до** валідації пароля, вхід миттєво відхиляється, а подія фіксується в аудит-лозі (`AuditEventType.LoginFailed: "Акаунт заблоковано"`).

## 2. Модель керування доступом (ЛР №5)

### 2.1. Обрана модель: Змішана RBAC + ABAC (Role-Based & Attribute-Based Access Control)
- **Рольова основа (RBAC):** Розподіл прав за функціональними обов'язками:
  1. **Гість (Anonymous):** Публічний перегляд каталогу, відправка заявки на підбір авто.
  2. **Менеджер (Manager):** Додавання, редагування лотів авто, перегляд повних розшифрованих VIN-кодів, перегляд собівартості, обробка заявок клієнтів.
  3. **Адміністратор (Admin):** Усі права менеджера + створення облікових записів персоналу, блокування співробітників, криптографічна перевірка ліцензії `dealer.lic`, перегляд Security Audit Log.
- **Атрибутна складова (ABAC):**
  - Атрибут `IsBlocked`: активний чи заблокований акаунт.
  - Атрибут власності/ролі при блокуванні: правило заборони самоблокування адміністратора (`user.UserName != currentActor`).

### 2.2. Правила розмежування доступу

| Ресурс / Операція | Гість | Менеджер | Адміністратор | Де виконується перевірка |
|---|---|---|---|---|
| Публічний каталог (`/Home/Index`) | Дозволено (маскований VIN) | Дозволено | Дозволено | `[AllowAnonymous]` |
| Залишити заявку (`/Home/SubmitRequest`) | Дозволено | Дозволено | Дозволено | `[AllowAnonymous]` |
| Перегляд повного VIN та собівартості | Заборонено | Дозволено | Дозволено | `[Authorize(Roles = "Manager,Admin")]` |
| Додавання / Редагування лотів авто | Заборонено | Дозволено | Дозволено | `[Authorize(Roles = "Manager,Admin")]` |
| Перегляд розшифрованих телефонів клієнтів | Заборонено | Дозволено | Дозволено | `[Authorize(Roles = "Manager,Admin")]` |
| Створення менеджерів (`/Admin/CreateManager`)| Заборонено | Заборонено | Дозволено | `[Authorize(Roles = "Admin")]` |
| Блокування акаунтів (`/Admin/ToggleBlockUser`)| Заборонено | Заборонено | Дозволено (крім себе) | `[Authorize(Roles = "Admin")]` + ABAC rule |
| Завантаження та перевірка ліцензії | Заборонено | Заборонено | Дозволено | `[Authorize(Roles = "Admin")]` |
| Перегляд Security Audit Log | Заборонено | Заборонено | Дозволено | `[Authorize(Roles = "Admin")]` |

### 2.3. Архітектурне забезпечення перевірки прав
Перевірка доступу виконується безпосередньо перед виконанням операції на рівні контролерів за допомогою фільтрів `[Authorize(Roles = "...")]`, а не лише шляхом приховування UI-елементів. Спроба прямого доступу за URL-адресою неавторизованим користувачем спричиняє перенаправлення на `/Account/Login`, а користувачем з недостатніми правами — HTTP 403 Forbidden (`/Account/AccessDenied`).
