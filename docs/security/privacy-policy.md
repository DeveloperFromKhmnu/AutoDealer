# Політика конфіденційності — AutoDealerCRM

**Версія:** 1.0  
**Дата:** 2026-11-02  
**Статус:** Актуальна

> Цей документ є внутрішнім нормативним актом навчального проєкту AutoDealerCRM.  
> У разі публічного розгортання системи цей документ підлягає перегляду та адаптації до вимог чинного законодавства (зокрема Закону України «Про захист персональних даних»).

---

## 1. Мета документа

Цей документ визначає, які персональні та конфіденційні дані збираються і обробляються системою AutoDealerCRM, з якою метою, де зберігаються, хто має до них доступ і які заходи захисту застосовуються.

---

## 2. Категорії даних, що обробляються

### 2.1. Персональні дані покупців (Гостей)

| Поле | Опис | Джерело |
|------|------|---------|
| ПІБ | Прізвище, ім'я, по батькові покупця | Форма заявки на підбір авто |
| Номер телефону | Контактний номер для зв'язку | Форма заявки на підбір авто |
| Побажання щодо авто | Текстовий опис бажаної моделі | Форма заявки на підбір авто |

Система **не збирає** від покупців: email-адреси, адреси проживання, платіжні дані, cookie-ідентифікатори для відстеження.

### 2.2. Конфіденційні комерційні дані

| Поле | Опис | Власник |
|------|------|---------|
| VIN-код автомобіля | Унікальний ідентифікатор транспортного засобу (17 символів) | Лот автомобіля |
| Собівартість закупівлі | Ціна, сплачена на аукціоні (USD) | Лот автомобіля |

Ці дані не є персональними даними фізичних осіб, але є комерційно чутливою інформацією дилера.

### 2.3. Облікові дані персоналу

| Поле | Опис |
|------|------|
| Логін менеджера / адміністратора | Ідентифікатор для входу в систему |
| Хеш пароля | Зберігається виключно у захешованому вигляді (PBKDF2) |
| Дата створення акаунту | Службова інформація |

---

## 3. Мета обробки даних

| Категорія даних | Мета обробки |
|-----------------|-------------|
| ПІБ та телефон покупця | Забезпечення зворотного зв'язку з потенційним покупцем для консультації |
| VIN-код | Ідентифікація автомобіля, перевірка його історії; відображення менеджеру та адміністратору |
| Собівартість | Розрахунок маржинальності; відображення менеджеру |
| Облікові дані персоналу | Автентифікація та авторизація в системі |
| Дані журналу безпеки (IP, логін, час) | Забезпечення підзвітності, виявлення несанкціонованого доступу |

---

## 4. Місця зберігання

- Усі дані зберігаються виключно у базі даних Microsoft SQL Server (LocalDB / SQL Express), розгорнутій локально на сервері дилера.
- Дані **не передаються** третім сторонам, хмарним сервісам або зовнішнім API.
- Резервні копії бази даних зберігаються локально за відповідальністю адміністратора.

---

## 5. Криптографічний захист

| Поле | Захист |
|------|--------|
| Номер телефону покупця | AES-256-CBC шифрування (EncryptionService) |
| VIN-код автомобіля | AES-256-CBC шифрування (EncryptionService) |
| Собівартість | AES-256-CBC шифрування (EncryptionService) |
| Пароль користувача | PBKDF2 хешування (ASP.NET Core Identity PasswordHasher) |

Ключ шифрування зберігається у конфігурації середовища та ніколи не вноситься у репозиторій.

---

## 6. Правила доступу до персональних даних

| Дані | Гість | Менеджер | Адміністратор |
|------|-------|----------|---------------|
| Публічний каталог (марка, модель, рік, пробіг, ціна, статус) | ✅ | ✅ | ✅ |
| Маскований VIN (перші 11 символів) | ✅ | ✅ | ✅ |
| Повний VIN (розшифрований) | ❌ | ✅ | ✅ |
| Собівартість лоту | ❌ | ✅ | ✅ |
| Заявки покупців (ПІБ, телефон) | ❌ | ✅ | ✅ |
| Журнал безпеки | ❌ | ❌ | ✅ |
| Облікові записи менеджерів | ❌ | ❌ | ✅ |

---

## 7. Строки зберігання

| Категорія | Строк зберігання |
|-----------|-----------------|
| Заявки покупців | До ручного видалення адміністратором або менеджером |
| Лоти автомобілів | Безстроково (архів дилера) |
| Записи журналу безпеки | Не видаляються через інтерфейс (захист від фальсифікації) |
| Облікові дані заблокованих менеджерів | Зберігаються у БД (не видаляються, лише блокуються) |

---

## 8. Принцип мінімізації даних

Система збирає лише ті дані, які необхідні для виконання своїх функцій. Зокрема:
- Від покупців не запитуються email-адреси, дати народження або ідентифікаційні документи.
- Журнал безпеки фіксує IP-адресу запиту, але **не зберігає** відбитки браузера, user-agent або cookies покупців.

---

## 9. Обмеження на запис у журнали

У будь-які лог-файли або журнал безпеки **забороняється** записувати:
- Паролі або їх хеші.
- Розшифровані значення VIN, телефонів, собівартості.
- Ключі шифрування або будь-які криптографічні матеріали.

---

## 10. Права суб'єктів даних (навчальний контекст)

У навчальному проєкті механізм реалізації прав суб'єктів (видалення, виправлення) не передбачений. У production-варіанті системи адміністратор несе відповідальність за обробку відповідних запитів від покупців.
